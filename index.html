High-Throughput Distributed Event Pipeline (Independent R&D Project)

Designed and built a modular, containerized event-driven ingestion pipeline from the ground up for real-time telemetry processing, dual-write state persistence, and low-latency caching. The architecture decouples data producers from downstream consumers using a Kafka-compatible messaging backbone powered by Redpanda.

Infrastructure & Cost Strategy (MSK vs. Containerized Redpanda): While fully managed streaming services like AWS MSK (Managed Streaming for Apache Kafka) offer reduced operational overhead, they carry substantial baseline financial footprints and rigid infrastructure minimums that heavily penalize independent development workloads and predictable mid-scale projects. To optimize cost without sacrificing performance, the design utilizes a containerized Redpanda engine orchestrated via Docker Compose. This approach delivers lightning-fast, Kafka-compatible wire protocol performance with minimal memory overhead, eliminating unnecessary cloud costs while preserving seamless horizontal scalability.

System Components:

  • Ingestion Producer: Parses high-volume input telemetry feeds and pushes serialized streaming payloads into the event broker.
  • Consumer Daemon Workers: Background worker nodes utilizing consumer group isolation to poll and process streaming events concurrently.
  • Dual-Store Persistence Engine: Implements safe transactional writes into PostgreSQL for immutable historical event logging, alongside atomic Redis hash updates for instantaneous operational lookups and real-time node state registries.

Selected Professional Case Studies

1. E911 SMPP Stateful Routing Engine & Session Proxy (C & Network Primitives)

Architected a high-throughput Short Message Peer-to-Peer (SMPP) routing engine in C to serve as a high-availability stateful proxy between an upstream Kannel application cluster and external emergency service providers (Comtech). Solved a critical network topology constraint: because the external provider operated under strict security architectures that rejected inbound connections, they required all TCP communication channels to be initiated externally and bound to our local site endpoints.

To bridge this gap, engineered a low-latency routing daemon that managed persistent, pre-established upstream transceiver binds. The engine safely decoupled the Kannel processes, intercepted outbound transaction payloads, mapped them to active connection pools, and reverse-routed inbound delivery notifications back to the correct originating backend worker nodes. Leveraged non-blocking socket I/O and POSIX concurrency mechanisms to ensure deterministic, sub-millisecond message delivery paths under highly volatile, mission-critical E911 operational loads.

3. Cross-System Session Correlation Engine & Performance Migration (Ruby → Go, Redis, Kafka)

Architected a high-performance distributed session tracking engine—originally developed in Ruby as the core platform standard—to correlate disparate inbound and outbound multimedia messages (MMS) across global operating regions (e.g., US and Europe). When a message is captured in one region, the system extracts metadata routing pairs, enterprise IDs, and payload checksums, streaming the events to a globally shared Kafka topic.

To optimize infrastructure limits and proactively insulate the primary PostgreSQL database from high-volume transaction write bottlenecks, I re-engineered the ingestion layer to buffer data directly into a low-latency Redis queue instead of executing direct database table writes. Furthermore, to leverage advanced performance fixes and robust cluster handling inside newer Kafka library toolchains, I spearheaded the technical migration porting the entire system from Ruby to Go. This structural pivot dramatically reduced the database I/O footprint, slashed execution latency bounds, and delivered a highly resilient, concurrent messaging layer across telecom zones.

6. High-Scale Data Ingestion Migration & AI-Assisted Porting (Ruby → Go, C, Kafka)

Engineered an end-to-end data ingestion engine in Ruby to process high-volume assets from cloud object storage (S3). The service streamed binary payloads to high-performance Network File Systems (NFS), generated tracked transaction rows across relational database tables, and synthesized Call Detail Records (CDRs) for downstream analytical consumption. Because the deployment environment operated under strict security air-gapping with zero public egress, I isolated the compilation toolchain, precompiled the underlying librdkafka C source library locally, and reverse-engineered the Ruby gem wrapper to package the static binaries locally—bypassing automated deployment blockades while maintaining security compliance.

Over time, maintaining the legacy environment exposed architectural limits. The underlying server OS and aging Ruby runtime versions blocked critical upstream librdkafka security patches and performance fixes from being compiled. Rather than continuously patching a constrained runtime environment, I drove the strategic decision to migrate the pipeline to an independent, cloud-native architecture optimized for highly concurrent execution. I spearheaded the comprehensive porting of the entire processing pipeline from Ruby to Go, leveraging the highly resilient Sarama framework for Kafka orchestration. I heavily utilized AI-assisted development workflows to rapidly translate business logic, generate idiomatic Go struct interfaces, and bootstrap robust validation testing suites. By acting as the strict manual verification guardrail, I audited all AI-generated outputs for memory management, type safety, and data consistency.

The migration yielded a compiled, single-binary Go service that completely eliminated the legacy OS/C-dependency compilation footprint, dramatically slashed CPU/memory utilization, and established a scalable, low-latency data consumer capable of processing millions of records with near-zero runtime maintenance.
